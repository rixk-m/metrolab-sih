# METROLAB — Reference Websites & Interaction Direction

## PURPOSE OF THIS DOCUMENT

This document defines how the selected reference websites should influence the METROLAB / NAWI OIML R76 prototype.

IMPORTANT:

The reference websites below are **NOT the websites we are building**.

We are NOT recreating their subject matter, branding, content, layout, imagery, or visual identity.

They are being used as **interaction, motion, visual-storytelling and UX references**.

The goal is to extract the strongest interaction ideas from them and reinterpret those ideas for a completely original:

**NAWI / OIML R76 / Digital Metrology Laboratory experience.**

The final METROLAB website must have its own identity.

---

# 1. PRIMARY REFERENCE — OPEN SBS / BRIG.HT CITY

Website:

https://open-sbs.brig.ht/city

## Reference Role

Use this website primarily as inspiration for:

**spatial exploration + interactive 3D environment + feeling of moving through a digital world.**

The site is an example of an interactive browser experience rather than a conventional information page.

## What to TAKE FROM THIS REFERENCE

### 1. Spatial Website Thinking

Do not treat the website as a stack of rectangular sections.

Think of the site as a world.

The user should feel that the page is an environment that can be explored.

For METROLAB:

The "world" becomes a:

**Digital Metrology Laboratory.**

---

### 2. 3D Scene as the Main Experience

The 3D scene should not be a decorative background.

It should be the visual foundation of the experience.

For METROLAB:

- weighing instrument
- calibration masses
- laboratory equipment
- measurement environment
- technical data elements
- test stations
- floating instrument information

should exist inside the same visual world.

---

### 3. Spatial Navigation

Take inspiration from the idea of navigating through a spatial environment.

Possible METROLAB implementation:

Scrolling can move the camera:

- toward the weighing instrument
- around the instrument
- toward specific components
- toward testing areas
- toward data displays
- toward the report-generation environment

---

### 4. Interactive Objects

Objects should have purpose.

Example:

Hover over weighing platform:

**INSPECT PLATFORM**

Hover over display:

**MEASUREMENT DISPLAY**

Hover over calibration mass:

**REFERENCE STANDARD**

Clicking should trigger:

- camera movement
- object focus
- information reveal
- animation
- scene transition

---

### 5. Depth

Use:

- foreground
- middle ground
- background
- atmospheric elements
- shadows
- lighting
- perspective

The user should perceive real depth.

---

### 6. Exploration Instead of Decoration

Every major 3D object should either:

- communicate a concept
- respond to interaction
- support storytelling
- represent a product feature

Do not put random 3D objects into the scene.

---

# 2. PRIMARY REFERENCE — MONT-FORT

Website:

https://mont-fort.com/

## Reference Role

Use Mont-Fort primarily as inspiration for:

**cinematic scrolling + visual hierarchy + large-scale typography + smooth transitions + premium presentation.**

The current Montfort site explicitly presents a scroll-led discovery experience, including a "Scroll down to discover" interaction and large visual sections. Its structure demonstrates how a corporate/product story can be presented through sequential visual experiences rather than a conventional card-heavy landing page.

## What to TAKE FROM THIS REFERENCE

### 1. Cinematic Scroll Storytelling

The user should not feel like they are simply scrolling through content.

Scrolling should reveal a sequence.

For METROLAB:

```text
WELCOME
    ↓
PRECISION
    ↓
THE INSTRUMENT
    ↓
THE PROBLEM
    ↓
DIGITAL TESTING
    ↓
OIML R76
    ↓
MEASUREMENT
    ↓
COMPLIANCE
    ↓
REPORT
    ↓
PLATFORM
```

---

### 2. Full-Screen Visual Moments

Use large visual compositions rather than many small cards.

Each major section should have a clear visual identity.

Example:

## PRECISION.

The instrument fills the environment.

Then on scroll:

## EVERY GRAM MATTERS.

The camera moves closer.

Then:

## EVERY TEST. VERIFIED.

The scene transforms.

---

### 3. Large Typography

Use typography as a visual object.

Do not treat headings as normal HTML labels.

Examples:

**PRECISION.**

**MEASURED.**

**VERIFIED.**

**ONE DIGITAL WORKFLOW.**

Words can:

- scale
- move
- split
- fade
- overlap
- reveal
- transform
- interact with the 3D environment

---

### 4. Section-to-Section Transitions

Do not abruptly switch from one section to another.

Instead:

- camera movement
- object movement
- typography transition
- background transformation
- lighting transition
- environment transformation

should connect sections.

---

### 5. Controlled Minimalism

Take the premium restraint.

Avoid:

- clutter
- excessive cards
- random UI elements
- too many colors
- unnecessary borders

Use fewer elements but give important elements more visual impact.

---

### 6. Navigation

Use minimal navigation.

A simple:

**METROLAB**

with:

**MENU**

can open an immersive navigation overlay.

The navigation itself can have animated transitions.

# 3. PRIMARY REFERENCE — DAVID WHYTE EXPERIENCE

Website:

https://davidwhyte.com/experience/

## Reference Role

Use this website primarily as inspiration for:

**immersive storytelling + visual atmosphere + artistic transitions + emotional pacing + experimental interaction.**

The David Whyte experience is explicitly positioned as an immersive digital journey and is associated with 3D visuals, interactive storytelling, sound and changing visual environments.

## What to TAKE FROM THIS REFERENCE

### 1. Opening Experience

The website should not immediately look like an enterprise dashboard.

Start with an atmospheric experience.

Example:

Dark screen.

Slow emergence.

Typography:

# WELCOME TO METROLAB

Then:

**A DIGITAL METROLOGY LABORATORY**

Then the environment begins to appear.

---

### 2. Storytelling Through Scroll

Use scrolling like a timeline/story rather than a document.

Each scroll movement advances the story.

Example:

The scale is distant.

Scroll.

The camera approaches.

Scroll.

The platform becomes active.

Scroll.

A calibration weight appears.

Scroll.

The display changes.

Scroll.

A calculation appears.

Scroll.

Compliance appears.

Scroll.

The data becomes a report.

---

### 3. Atmospheric Visuals

Use controlled environmental changes:

- darkness/light
- haze
- subtle particles
- reflections
- shadows
- soft gradients
- changing illumination

The purpose is to create mood and depth.

Do NOT copy the watercolor aesthetic.

METROLAB should have a:

**precision laboratory / industrial / technical aesthetic.**

---

### 4. Continuous Experience

Avoid making every scene feel like a new webpage.

The user should feel that the same environment is transforming.

The weighing instrument can evolve throughout the journey.

For example:

```text
PHYSICAL INSTRUMENT
        ↓
TECHNICAL INSPECTION
        ↓
MEASUREMENT
        ↓
DIGITAL DATA
        ↓
COMPLIANCE
        ↓
REPORT
```

---

### 5. Interactive Visual Storytelling

Use interactions to explain concepts.

Example:

When the user scrolls to the eccentricity test:

The reference mass moves to different positions on the weighing platform.

When the user reaches repeatability:

The test is repeated visually.

When the user reaches compliance:

The observed value is compared against the configured permissible limit.

The user should understand the concept without needing to read a large paragraph.

---

### 6. Restart / Replay Experience

The reference includes an explicit "Restart the experience" interaction.

Use this concept for METROLAB.

Provide:

**REPLAY EXPERIENCE**

at an appropriate point.

It should smoothly return the experience to the beginning rather than simply refreshing the browser.

# 6. REQUIRED METROLAB INTERACTION LANGUAGE

The final prototype should contain as many of these interaction patterns as they genuinely improve the story:

## Scroll-driven camera

Scrolling moves the camera through the 3D world.

## Scroll-driven object animation

Objects rotate, move, appear, disappear or transform.

## Scroll-driven typography

Typography changes based on scroll progress.

## Mouse parallax

Cursor movement subtly changes camera/environment position.

## Interactive hotspots

3D objects can be inspected.

## Hover states

Interactive objects react visibly.

## Click-to-explore

Important objects can be selected and focused.

## Pinned scenes

The 3D environment remains while the story changes around it.

## Horizontal movement

Use horizontal spatial movement only where it improves the story.

## Morphing transitions

Physical objects can visually transform into digital representations.

## Data visualization inside 3D

Measurements and test results can appear as spatial information.

## Custom cursor

A minimal cursor that becomes contextual when interacting.

## Smooth scrolling

Use inertial/smoothed scrolling.

## Scene transitions

Avoid hard page-to-page jumps.

## Loading experience

The opening/loading sequence itself should establish the product identity.

## Replay

Allow the immersive experience to be replayed.

# 10. INTERACTION DEPTH

There should be multiple layers of interaction.

## Layer 1 — Scroll

Changes the story.

## Layer 2 — Mouse

Changes perspective.

## Layer 3 — Hover

Reveals interactive objects.

## Layer 4 — Click

Opens/focuses information.

## Layer 5 — Application

Allows the user to actually perform the workflow.

This makes the website feel like a real interactive product rather than a video disguised as a webpage.

# 15. TECHNICAL INTERACTION DIRECTION

The intended experience should be achievable using technologies such as:

- Three.js
- React Three Fiber
- Drei
- GSAP
- GSAP ScrollTrigger
- Lenis
- Framer Motion
- WebGL
- optimized GLTF/GLB assets

GSAP ScrollTrigger is appropriate for synchronizing animation timelines with scroll progress, including scrubbing and pinning.

The architecture should keep the 3D experience modular so individual scenes can be optimized or replaced without rewriting the entire application.

# 17. REFERENCE PRIORITY

When there is a design conflict, prioritize in this order:

1. METROLAB product purpose
2. Usability
3. 3D interaction quality
4. Scroll storytelling
5. Visual hierarchy
6. Performance
7. Accessibility
8. Aesthetic experimentation

Do not sacrifice usability or technical correctness solely for visual effects.
