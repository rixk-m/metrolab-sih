# Acceptance Criteria

## Core Workflow
A demo user must be able to:
1. Log in.
2. Create/select an instrument.
3. Create an evaluation.
4. Enter technical and laboratory data.
5. Configure applicable tests.
6. Enter observations.
7. Receive validated calculations.
8. Receive a configured compliance result.
9. Attach evidence.
10. Submit for review.
11. Reviewer can request changes or approve.
12. Generate a standardized report.
13. Store the report in the repository.
14. View instrument history.
15. View audit events.
16. Enforce role permissions.

## Public Experience
The site must:
- start with strong typography
- support dark/light modes
- use meaningful interactive 3D
- react to scrolling
- move the camera
- use purposeful object interactions
- explain NAWI evaluation visually
- connect physical instrument concepts to digital workflow
- enter the actual application.

## Calculation
No unavailable/unconfigured rule may silently produce a compliance decision. Results identify the ruleset/version.

## Reports
Correct data, metadata, calculations/results, evidence, revisions and clean rendering without clipping.

## Security
Unauthorized access or modification must be prevented.

## Accessibility
Core workflows cannot depend solely on mouse interaction.
